# Design

## A send saves what was typed before it holds the prose

Holding a report's prose still for a send first saves what was typed and not yet saved, through the same save that names its writers, and waits out a save already under way. The send then stores words that are already attributed. A save that fails leaves the report unsent, holding nothing.

Saves of one record's prose run one at a time and in order, so a later save never lands before an earlier one.

## A reorder answers with the versions it left

A reorder answers every row it arranged at the version it now holds. The screen writes those versions into what it holds as soon as the answer arrives, and runs its reorders of one set of rows one at a time, so each one is sent with what the last one left.

## The freeze passes three writes the store makes for another

A write the store issues on behalf of another passes the freeze only where that other is the case's removal, an account's removal with its name cleared from what it wrote, or a piece of evidence's removal with a sent figure's pointer to it cleared. The figure was frozen with the document and is drawn by its content, so the pointer is not what was sent, and refusing the removal would hold the evidence for a reference nobody can release. Every other such write, the reference to a removed predecessor among them, is refused, so the removal that caused it is refused with the sent report's refusal.
