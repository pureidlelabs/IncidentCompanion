# Scope

**Words accepted from a writer who has since lost write are stored only through a writer who still has it.** Where nobody who wrote into a document since it was last stored may still write it, the words stay unsaved and the install logs it; whether they should be kept regardless is the socket work's question.

# Design

## Who a live document is stored as

A document keeps everyone who wrote into it on this process since it was last stored, the latest last. Storing it asks the store as each of them in turn, latest first, and stops at the first the store lets write the row. A store that takes it from none of them, or finds no row, leaves the document unsaved with its writers kept and logs it, so the next quiet moment or the last reader leaving tries again. A row the store refuses to change is not an error, so an update matching nothing is read as a refusal rather than as done.

## The store's own move

The move act answers whether a case moved, and when it did not, why: the mover does not write the case where it is, the destination is the default customer, or the case carries a reference and the mover does not reach the destination. It decides all three from who is asking before it changes anything, and without looking at what the destination holds. The route maps each answer; the reference check it keeps can find a collision only where the mover can see the destination's cases.

## A refusal for reach is an answer

A write the store refuses for reach, inside the scope that names a case, is answered as that case not being there, with the store's refusal kept as the cause.

## Acts that see past every caller

Every act the application may call is one of three kinds: it answers about the principal or one case they name, it answers an administrator, or it is asked for nobody and answers digests and counts with no case beside them. The case tally is an administrator's. A new act is classed before it can be called.

## The level an administrator is shown

The role's floor is its own answer in the store, and the level is the strongest of the floor and every grant. An administrator's view of somebody's reach takes both from the store and names the grant behind the level: the floor where it already gives that level, else the group that grants it.

## A refusal after the account is gone

An audit line names its actor's account only where the install holds it, and keeps the name the session carried either way.
