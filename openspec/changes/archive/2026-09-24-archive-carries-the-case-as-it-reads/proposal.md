# An archive carries the case as it reads, and writes only what an install could

## Why

An archive is handed to a customer, a regulator or another organisation, and it carried how the case came to read rather than how it reads: every passage an analyst deleted before the handover, a section they removed, and a section turned into one no view shows (#1164). Its record could also plant what no install writes: any note document (#1171), a report's lifecycle in three states `send` never produces (#1169), a value its collection's own rules refuse (#1170), and as many rows as the file cared to state (#1172). The record kept every deleted keystroke too, so the archive was one door of several.

## What Changes

- **case-archive**: an archive carries the prose as it reads, a note's included, and never a deleted passage or a removed section; it is bounded in the rows it describes, refused before any is written; its report lifecycle is whole or refused, and its preserved document is checked and contained; a row is refused where its collection's rules spanning fields refuse it; damage is refused for every archive, and alteration is refused for a sealed one (maintainer decision, 2026-09-23).
- **live**: deleted prose is not kept, and a removed section takes its prose with it.
- **report**: a report is sent and preserved, or neither, whichever writer; what the install generates in a document that leaves it carries no live indicator.

## Impact

- Every prose document collects deleted content; no route reads a past state of prose.
- No HTTP answer carries a prose document.
- An operator sets the archive row ceiling as `evidence.archiveRows`.
